Pgweb (sosedoff/pgweb) unauthenticated SQL access and OS command execution PoC
Endpoints: GET /api/info -> GET /api/query?query=<SQL>
Collection date: 2026-10-20    Environment: public Internet hosts
# Public host identities are redacted; 192.0.2.x addresses are placeholders.
================================================================================
Notes:
- Pgweb does not enable HTTP authentication unless configured; /api/query
  accepts SQL from unauthenticated visitors when the service is exposed.
- With a superuser database connection, PostgreSQL COPY ... TO PROGRAM can
  invoke /bin/sh as the database service process user (postgres in the container).
- The probe used four steps per host: write marker -> read back -> remove ->
  verify removal. A separate SQL query checked the connected role first.
- The probe wrote only the fixed string NCCPROBE to /tmp/ncc_pg_probe. It did
  not install a web shell, create a reverse shell, read other files, or modify
  application data. Removal was verified on all three hosts.
- Public target addresses below have been replaced with reserved documentation
  addresses (192.0.2.0/24). Database identifiers have been fully redacted.
  Status codes, SQL, marker output, and other non-identifying evidence remain.

================================================================================
Conditions and source locations (Pgweb 0.17.0, commit 6b0b0244)
================================================================================
- HTTP layer: cli.go:202-206 attaches gin.BasicAuth only when AuthUser and
  AuthPass are both nonempty. Neither option has a default in options.go:44-45.
  Dockerfile:48 starts with --bind=0.0.0.0 --listen=8081.
- SQL layer: api.go:312,556 passes RunQuery -> HandleQuery -> client.Query
  without restricting the SQL statement type.
- Database layer: The connected role was a superuser in these cases. PostgreSQL
  also allows COPY ... TO PROGRAM for roles with pg_execute_server_program.
  Common docker-compose deployments may connect using the postgres superuser.
- Observed chain: unauthenticated /api/query -> COPY ... TO PROGRAM -> OS command
  as the database process user -> output read back via pg_read_file.
